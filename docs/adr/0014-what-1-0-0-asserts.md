# ADR-0014 — What `1.0.0` asserts

- **Status:** accepted
- **Date:** 2026-09-20
- **Amends:** [ADR-0013](./0013-a-config-is-data-not-a-program.md), whose `--migrate-config` is withdrawn

## Context

The package sat at `0.5.0` and read as unfinished to anyone deciding whether to depend on it. No document in this repository said what `1.0.0` would mean, so the question had no answer to consult and was re-argued every time it came up.

It was also being argued from the wrong premise. This project measures itself against [ADR-0006](./0006-the-m1-precision-criterion.md)'s nine conditions as amended by [ADR-0009](./0009-precision-is-counted-in-quiet-repos.md), so "are we at 1.0?" kept being read as "are the conditions met?" — and condition 6 is not met. It stands at **58 of 66 repositories with no false positive, 87.9%, against a 90% bar** (the validation group alone is 29 of 32, 90.6%).

Meanwhile the surface a `1.0.0` would freeze was not honest enough to freeze. `--strict` and `--watch` were advertised in `--help`, parsed, and then exited 2 saying they were not implemented. `SPEC.md` documented a `--no-group` flag no code had ever known about. The config accepted, validated and carried three keys nothing read. Three types were reachable through the published API and could not be named. § 6's JSON example omitted a key the reporter always emits.

## Decision

**`1.0.0` is a claim about compatibility, not about quality.** It says the public surface stops moving without a major version. It says nothing about precision, and precision never gates a release: the number is published every round, whatever it reads.

### What is frozen

Eight surfaces, named, because "the public API is stable" without a list is a promise nobody can check:

1. The exit codes and their meanings.
2. The check ids.
3. The CLI flag names and what they do.
4. The `--json` contract: top-level keys, `summary` keys, per-finding keys.
5. The shapes `--format github` and `--format sarif` emit.
6. The config file format: the accepted keys, and the refusal of unknown ones.
7. The names exported from the package entry point.
8. The Node floor in `engines`.

They are listed, in full, in [`CONTRACT.md`](../../CONTRACT.md) — generated by `pnpm surface`, committed, and held to the code by `test/surface.test.ts`. That file is the operative half of this ADR: breaking the contract is a diff in it that somebody has to accept.

### The version policy

| change | version |
|---|---|
| a new tier 1 check (defaults to error) | major |
| a new skills root | major |
| raising the Node floor | major |
| a new tier 2 check (defaults to warning) | minor |
| narrowing a check, tuning a discard rule | minor |
| adding an optional field to an existing output | minor |

**The lower half is free rather than disciplined.** A tier 2 check defaults to warning, and the exit code ignores warnings unless `--strict` is passed — so a tier 2 check cannot turn a green run red, by construction and not by care. That is why the rule is affordable: the four checks M5 still owes cost one minor between them.

The upper half has a price and it was accepted with the price named. Under this policy `0.5.0` would have been a major: it added `.github/skills/` and two more skills roots, and repositories that had changed nothing began to report. **The next skills root is `2.0.0`.**

### What was made honest first, in the same release

- `--strict` is implemented: warnings count toward the exit code when it is passed.
- `--watch` is out of the parser and the help text. It belongs to M6; until then it fails as any unknown flag does.
- `--no-group` is deleted from `SPEC.md`.
- `ignore`, `knownPaths` and `staleThreshold` are out of the config's accepted keys and out of what `--init` writes. `staleThreshold` returns with `stale/churn`, which is a minor above.
- `Finding`, `SkippedSource` and `DiscardSink` are exported. Their shapes were already public through `RunResult` and `RunOptions`.
- `SPEC.md` § 6's example carries every key the reporter emits, and a test holds it there.
- `--migrate-config` is withdrawn — see below.

`--no-tier2` is frozen as it stands. It filters tier 2 checks correctly and there are none to filter, which is a correct answer rather than a broken flag; it starts meaning something the day a tier 2 check exists, with no change.

### Two smaller things, settled here

**The JSON document's own `version` is independent of the package version.** It is `1` and the package is `1.0.0`; they are two clocks and their agreeing today is a coincidence. A `2.0.0` does not imply a JSON `version` of 2, and a JSON `version` of 2 would be a major whatever the package number was doing.

**The precision number's source is [`test/corpus/CLASSIFICATION.md`](../../test/corpus/CLASSIFICATION.md).** Everything else that publishes it — the site, the guide, the README — is derived from the snapshots by `pnpm site-data` and held by `test/site-data.test.ts`. The site published `92.4%` for two rounds after the repository read `87.9%`, because nothing recomputed it; that is why the source is named in an ADR rather than left to habit.

## Why precision does not gate the version

The rule matters less than the reason, because the reason is what stops it being reversed in six months.

**Tying the version to condition 6 manufactures pressure to close false-positive classes in order to move a number.** That is the one move [`CLASSIFICATION.md`](../../test/corpus/CLASSIFICATION.md) forbids, and two tickets have already refused it — once by saying no to the cheapest repository in the corpus. A release calendar that rewards reclassifying a finding is a release calendar that will eventually get a finding reclassified.

**The measurement is out of sample and the version is not a measurement.** Precision is counted over 66 repositories a person has read, half of them held out. Whether the tool is ready to promise a stable CLI is a question about the CLI. Neither answer is evidence for the other.

**The criterion has to survive failing.** It was chosen under the constraint that it would be acceptable for it to go unmet for six months — so that it is not a criterion written around the numbers of the day it was written, which is the mistake ADR-0009 names when it refuses to replace a threshold with one today's figures would pass.

So: **87.9% stays published and stays unmet.** ADR-0006's answer to a failing condition is unchanged and is still the only one — go back to the heuristics, or accept that the check does not get there and say so. What is new is only that neither of those is a reason to withhold a version number.

## Why `--migrate-config` is gone

ADR-0013 withdrew `.ts`, `.js` and `.mjs` configs and shipped `--migrate-config` in the same commit, on the argument that a withdrawn format with no route off it moves a cost onto users. That argument is still right, and the flag is still gone.

It was a flag that ran a user's code on request, which is the one thing that ADR exists to stop driftwatch doing, and `1.0.0` is where the surface stopped carrying anything it would not want to carry for the life of a major version. **The obligation outlives the flag**: the route is now `npx @abr4xas/driftwatch@0.5.0 --migrate-config`, the last release that carries the converter, needing no install because `npx` is the advertised way to run this tool anyway. The loader's refusal for a module config says exactly that, so a reader meets the route at the moment they need it.

The two ADRs do not contradict each other. ADR-0013 promised a route, not a flag, and [its own status line](./0013-a-config-is-data-not-a-program.md) points here.

## What is lost

**Freedom to add a tier 1 check.** The four M5 owes are tier 2 by design, so this costs nothing today — but a check that ought to default to error now waits for a major, or ships as a warning it does not deserve. Accepted: a consumer's green run turning red in a minor is worse than a check arriving a version late.

**Freedom to add a skills root**, which is the same trade with a sharper edge, because a new root reports on repositories that changed nothing. Machinery for staging a root — off by default in a minor, on at the next major — was considered and rejected in favour of the simpler rule. A staged root is a check that behaves differently depending on when you installed it, which is worse than waiting.

**The option of using the version to signal quality.** `1.0.0` will be read by some people as "the precision is good now". It is not what the number says, and this document is where that is written down.
