# The checks

Five checks run today, all tier 1. Each one answers a question about the repository that a context file already claimed to know the answer to.

Every check can be turned off by id — `--skip link/broken`, or the `checks` key in the config — and silenced on a single line with an [ignore directive](./usage.md#ignore-directives).

---

## path/missing

**A context file names a file or directory that is not in the repository.**

This is the check that pays for the project. The paths are what an agent acts on: it reads the claim, believes it, looks for a file that is not there, and then guesses.

It fires on a fragment that **asserts existence**, which is much narrower than "looks like a path". Discarded before anything is reported: a path inside a URL, a glob or a placeholder (`<name>`, `{{path}}`, `$VAR`, `[id]`); a bare word with no slash; a single-segment directory like `feat/`, because people use `name/` for categories and branches; a path whose shape exists somewhere else in the repo; anything git ignores or that lands in a build output; a path the surrounding line hedges ("such as", "if exists", "(optional)", "is generated by", an opening "Create …"); a line linking to a different repository; and another assistant's configuration root in a repo that does not use that assistant.

[precision.md](./precision.md) has the full argument and the eleven classes that were closed one at a time.

**Suggests** a replacement when exactly one file in the repo carries that basename and sits close to where the document says. **Fixable** — see [fixing.md](./fixing.md).

## script/missing

**A document tells you to run a command whose script is defined nowhere.**

Detects `npm run S`, `pnpm run S`, `yarn run S`, `bun run S`, `deno task S` and `make S`, in code blocks and in inline code. Verified against `package.json#scripts` (the nearest one up the tree, so a monorepo works), `Makefile`, and `deno.json#tasks`.

Three refusals shape it:

- **No manifest anywhere means silence.** There is nothing to verify against.
- **The script only has to exist somewhere**, not in the nearest manifest — ADR-0005 applied to scripts. The nearest manifest is still what the message names, because it is the file you will open.
- **A manifest whose tasks cannot be enumerated answers nothing.** A `Makefile` with an `include`, a `deno.jsonc` that did not parse: the target may be perfectly real and living where we did not look.

A bare `pnpm x` is not a script claim ([ADR-0012](../adr/0012-a-bare-pnpm-x-is-not-a-script-claim.md)).

**Suggests** a correction when one script in the nearest manifest is within two edits of what was written. **Fixable.**

## link/broken

**A Markdown link carries a `#fragment` no heading in the target produces.**

The other half of a broken link — a target file that does not exist — is reported by `path/missing`, which extracts the path half of every link and suggests a candidate for it. So one broken link produces one finding, and the one that survives is the one carrying the suggestion.

Anchors match on a canonical key rather than a reimplementation of GitHub's slug algorithm: lowercase, then drop everything that is not a letter or a number ([ADR-0010](../adr/0010-anchors-match-on-a-canonical-key.md)). That is strictly more permissive than the real slug, so the divergence can only ever cost a detection, never produce a false report.

**Suggests** a near heading. **Never fixable** — see [fixing.md](./fixing.md#what-is-never-rewritten).

## frontmatter/invalid

**The YAML block at the top does not parse, or a key whose type the format fixes holds something else.**

Two checks wearing one id, carrying very different risk. The first is a fact: the block either is YAML or it is not, and a parser we did not write says which. The second needs a schema, and a schema we get wrong reports a field every real consumer accepts — so only keys whose type the format fixes are checked, and everything else in a block is the author's business.

An unknown key is only ever reported as a near miss of a known one ([ADR-0011](../adr/0011-an-unknown-key-is-only-reported-as-a-near-miss.md)).

**Never fixable.** The only such finding in 66 real repositories was an unquoted `description:` whose text already contained double quotes: quoting it would mean escaping them, and a `--fix` that escapes is a YAML serializer.

## skill/frontmatter

**A `SKILL.md` frontmatter is not invocable.**

Structure, and only structure: a missing required field (`name`, `description`), a `name` that is not the directory the skill lives in, a `name` that is not kebab-case, a description too short to make the skill discoverable. A field whose *type* is wrong is `frontmatter/invalid`'s finding, and a block that does not parse produces one finding rather than six.

**Suggests** the directory name for a wrong `name`. **Fixable**, and withheld when the directory name is not itself kebab-case — correcting a name to something equally invalid is not a fix.
