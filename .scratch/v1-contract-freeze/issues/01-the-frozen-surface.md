# 01: The frozen surface, generated and pinned

**What to build:** the artifact that makes breaking the contract a diff somebody has to accept
rather than a thing somebody notices. It lists everything `1.0.0` freezes — the exit codes and
their meanings, the check ids, the CLI flags, the `--json` top-level, `summary` and per-finding
keys, the other output formats' shapes, the config's accepted keys, the names the package
exports, and the Node floor. A script emits it, the artifact is committed, and a test asserts
the committed copy is what the script emits now.

It captures the surface **as it stands today, defects included**: the flags that are advertised
and refuse to run, the config keys nothing reads, the types that cannot be named. Every ticket
after this one is verified by the diff it makes here, so this one must go in before them and
must not tidy anything on the way past.

The JSON key sets come from a real run over a temporary repository rather than from reading the
reporter, so the artifact records what is emitted and not what was intended. Everything else is
derived in process from the source modules: the suite does not depend on a build step.

Prior art worth reading first: the corpus bookkeeping test, which holds a document to the
snapshots it describes, and the site data test, which holds a page's prose to a generated
artifact. Both exist because an artifact nothing recomputes is an artifact that drifts.

## What was built

`scripts/release/surface.ts` emits the artifact and writes `CONTRACT.md` and nothing else;
`pnpm surface` runs it; `test/surface.test.ts` regenerates it in process and fails when the
committed copy and the code disagree, printing one line per fact that moved rather than a
wall of text. Verified by mutating the committed copy: flipping `--strict` to `implemented`
fails with `gone: ... advertised, implemented` and `new: ... refused at runtime`.

**It lives at the repository root, not under `docs/spec/`.** That directory is primary source,
and `AGENTS.md` says that when it and the code disagree you decide which one is wrong. A
generated mirror can never be the wrong one, so filing it there would create a document the
rule does not apply to, which is a trap for the next reader. The root is also where a reviewer
meets it in a diff.

**Two runs are observed, not one.** The first fixture skips a source (a dangling symlink, the
shape an uninitialised submodule leaves behind) and the second does not. With a single
observation SARIF's `invocations` — emitted only when there is something to say about the run
itself — would have been recorded as a key that is always there, which is a promise nobody
made. Optionality is counted: a key is optional when some instance of its container did not
carry it, which is also how `findings[].suggestion` comes out right.

The fixture asserts its own shape before anything reads it: a finding with a suggestion, a
finding without one, something fixable, and a skipped source in the run that is supposed to
have one. A fixture that quietly stopped producing one of those would shrink the contract, and
a shrunken contract is the failure this artifact exists to make impossible.

**Two internals became exported**, `OPTIONS` in `src/cli/args.ts` and `UNIMPLEMENTED_BOOLEANS`
in `src/cli/main.ts`. Neither adds anything to the package's public API. They are what lets the
flag list carry three separate facts — accepted by the parser, advertised in `--help`, refused
at runtime — which is the only way today's defect is visible rather than averaged away.

### The defects it records, unaltered

- `--strict` and `--watch`: advertised, refused at runtime. Tickets `02` and `03`.
- `ignore`, `knownPaths` and `staleThreshold`: accepted config keys that nothing reads.
  Ticket `03`.
- `Finding`, `SkippedSource` and `DiscardSink`: absent from the exported names, which is how
  "reachable and unnameable" shows up in a list of what can be named. Ticket `05`.

Each of the three is a diff in this file when its ticket lands, which is what the ticket meant
by every one after it being verified here.

### What was not run

`pnpm corpus --check` was not run and is not required: nothing under `src/extract/` or
`src/verify/` was touched, no `fixable` flag moved, and no heuristic changed. The gate before
`08` still owes it.
