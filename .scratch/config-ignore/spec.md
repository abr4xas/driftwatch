# `ignore`: the key that lets a user say "not this document"

## The question this answers

A repository carries documents it did not write. A skill installed from somebody else, a
vendored upstream's `AGENTS.md`, a template's scaffold, a fixture tree. They name paths, the
paths are not in this repository, and driftwatch reports them.

[ADR-0008](../../docs/adr/0008-a-specification-is-not-an-agent-context-file.md) settled what
that is: *an agent context file makes assertions about the repo it sits in … point it at a
document that quotes rather than asserts and the check is not being noisy, it is being asked
the wrong question.* And it settled how to answer it — **with configuration**. This repository's
own `docs/spec/` and `docs/adr/` produced 43 findings and every one was a false positive; the
fix was one line of `sources`, not a heuristic.

Ticket [`36`](../corpus-adjudication-at-scale/issues/36-does-jev-know-whose-document-this-is.md)
then established that configuration is the *only* available answer, and measured it rather than
argued it:

- A model cannot draw the line. `aboutThisRepo` scored **-31 points** against a person.
- Neither can the disk. Eleven comparable pairs, and every deterministic axis —
  provenance metadata, the document copied into other repositories, the container directory,
  naming another project — appears on both sides of the distinction.

So there is no rule to write. What is left is to let the user say it, and today they cannot.

## Why the existing routes do not cover it

| route | why it falls short |
|---|---|
| `sources` | **Additive.** It adds documents to what discovery found; there is no way to subtract. |
| `checks: { 'path/missing': 'off' }` | Turns the check off **everywhere**, not in one directory. |
| `<!-- driftwatch-ignore-file -->` | Works, and requires **editing the document**. A skill installed from somebody else is overwritten on its next update, and editing another project's file to quiet your linter is the wrong move anyway. |
| `--skip path/missing` | Same as `checks`, and per-run rather than committed. |

The inline directives are the right tool for *your own* document — a line describing a file you
plan to create. They are the wrong tool for a document you do not own.

## What it is

```yaml
ignore:
  - '**/fixtures/**'
  - '.claude/skills/vendor-*/**'
  - 'third_party/**'
```

A list of globs, matched against **source paths relative to the repository root**. A document
whose path matches is not audited: it is not discovered, it produces no findings, and it is not
counted as skipped — it was never a source.

That shape is not invented here. `ignore` was specified in `SPEC.md` § 7 from the start, with
`['**/fixtures/**']` as its worked example, and was withdrawn in `1.0.0` by
[ticket `03`](../v1-contract-freeze/issues/03-stop-advertising-what-it-does-not-do.md) for being
accepted, validated, carried into the run and read by nobody. This implements the key that was
already designed; it does not design a new one.

## The rules it has to obey

1. **`ignore` beats `sources`.** A path matching both is ignored. Subtraction after addition is
   what every tool that has both does, and the opposite order makes `ignore` unable to do the
   one thing it exists for.
2. **It applies to discovered sources too**, not only to the ones `sources` named. A skill
   installed under `.claude/skills/` is found by discovery; an `ignore` that could not reach it
   would miss its whole motivating case.
3. **It never silences a claim by its target.** `ignore` takes the path of the *document*, not
   the path a document claims. Silencing `src/generated/**` wherever it is mentioned is a
   different feature with a different risk, and it is not this one.
4. **A glob that matches nothing is not an error.** `sources` errors on a path that does not
   exist, and it is right to: a source you asked for and did not get is a silent hole in the
   audit. The opposite holds here — an `ignore` entry for a directory a repository does not
   have yet is a config that keeps working, and failing on it would punish sharing one config
   across repositories.

## What it costs, stated plainly

**An ignored document's real drift goes unreported.** That is the point of the key and it is
the user's decision, made explicitly, in a file they committed — which is the difference
between this and a heuristic that decides the same thing on their behalf.

It is also the reason rule 3 above is a rule: a glob over claim targets would silence drift the
user never looked at, across documents they do own.

## Version

**Minor.** ADR-0014's policy puts a new accepted config key in the lower half — it adds surface
rather than reshaping it, and a config that does not use it behaves identically. `CONTRACT.md`
grows a row and is regenerated by `pnpm surface`, which is what records the change as
deliberate.

## Out of scope

- Negated patterns inside `ignore` (`!keep/this.md`). No evidence anyone needs them, and they
  make precedence a question rather than a rule.
- An `ignore` that takes check ids per glob. `checks` already exists, and the combination can
  be added later without breaking anything.
- Anything that infers what to ignore. That is exactly the hypothesis ticket `36` killed.
